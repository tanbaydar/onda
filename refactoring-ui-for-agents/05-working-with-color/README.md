## Chapter doctrine

- Reason about hue, saturation, and lightness rather than manipulating opaque codes blindly.
- Build a role-complete palette, not a decorative set of five swatches.
- Define shade families before components proliferate one-off variations.
- Adjust saturation and sometimes hue as lightness changes; numeric uniformity is not perceptual uniformity.
- Use tinted neutrals deliberately to establish temperature.
- Solve contrast within hierarchy instead of defaulting to the loudest possible surface.
- Color supports meaning; it is never the sole signal.

## Authority note

This chapter explains design reasoning, not a required storage format. If a project uses hex, RGB, HSL, OKLCH, platform color assets, or another approved system, preserve it. Accessibility calculations and thresholds must follow the project’s current authoritative standard, which may evolve beyond the source book’s examples.
