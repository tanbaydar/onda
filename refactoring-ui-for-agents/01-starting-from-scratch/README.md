# Starting from Scratch

This chapter governs how an agent begins design work. It prevents shell-first layouts, premature visual detail, speculative scope, personality drift, and arbitrary low-level choices.

## Chapter outcome

Before high-fidelity implementation begins, the agent should have:

- A named user job and smallest useful feature.
- Real content and actions, not an abstract application shell.
- A low-detail composition that works in grayscale.
- A bounded shipping slice with no implied unapproved functionality.
- A product personality translated into concrete visual decisions.
- A constrained set of system values from which implementation choices will be made.

## Stop conditions

Stop and seek clarification when:

- The requested visual direction contains only adjectives and no product context.
- A proposed layout implies functionality that is not approved.
- No authority exists for a personality-changing choice such as a new typeface, palette, radius language, or tone.
- A new value system would conflict with existing tokens or approved components.
